# 审核用语与失败修正入口

日期：2026-11-06。范围：本地定制类脚本局部更新的审核呈现、旧字段兼容及失败后修正入口。未部署线上代码、未代用户付费生成。

## 已确认问题与处理

现有失败候选的审核指出故事结构说明仍保留旧配色，而正文等其他内容已改色。这段历史文本存在于旧脚本 JSON 中，之前没有进入精确补丁白名单和请求 Schema，导致正常正文修改后它仍无法同步修改。

首次修复根据审核所写 `story.structure` 加入嵌套兼容字段，但误将根级 `structure` 当作类型排除。随后用户再次失败，读取实际冻结任务确认：旧配色实际位于根级叙事结构说明，脚本没有嵌套 `story.structure`。首次测试只覆盖了假设的嵌套形状，未覆盖真实问题，不能据此认定已解决。

后续修正将根级说明纳入 Contracts 精确补丁、Worker 的实际字段 Schema 和候选编辑；提示词明确区分叙事说明与 `settings.structureMode` 等类型配置，要求同步核对产品事实。身份、创作类型、时长及未涉及的文本仍受保护。历史嵌套字段仅在确实存在时兼容。

审核意见在 API 候选读取和工作流审核详情中将字段引用转换成普通中文，例如故事结构说明、脚本正文、故事段落、产品名称和产品外观。原始审核记录、引文事实和脚本内容不被迁移或改写；非审核节点的正文不会经新增格式转换。

候选返回可选的审核状态及问题/依据/建议。前端明确给出下一步，并在候选窗口和本方案状态区提供“按审核意见修正”，点击只进入原有更新范围预览。确认后才创建新任务；审核未通过稿不允许直接采用，原脚本继续保留。

新任务只在同项目、Run、脚本、信息卡 ID/revision/指纹、脚本基线及候选审核哈希一致时携带失败候选和原始审核意见；Worker 仍输出相对原始基线的完整必要补丁，再独立审核，不增加自动返修循环或版本树分支。旧失败记录保留。恢复语义审核失败的旧任务返回使用修正入口的清晰提示，避免重新读取同一失败审核后立即再次失败。

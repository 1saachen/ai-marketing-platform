# 脚本局部修改校验与检查点

日期：2026-11-06。作用域：本地定制类脚本局部更新 Worker 和失败原因投影；未部署线上代码或触发付费生成。

## 观察与结论

用户对方案三连续两次更新失败。Worker 日志显示两次 STORY 模型请求均返回 200，随后、成功步骤写入之前出现 `ValueError`。冻结任务的 STORY 仍为 RUNNING，审校与保存未执行。结合执行顺序，可以确定错误发生在应用改稿补丁的校验环节，与此前 401 鉴权问题不同。

旧流程没有先保存模型返回的补丁，也没有把应用异常写到步骤错误中；因此不能恢复这两次具体输出，无法进一步断言是哪条路径、原文定位或长度检查触发。原脚本没有被覆盖。

## 修正边界

- 请求 Schema 中的 path 枚举只包含冻结脚本实际已有的可编辑文本字段；说明明确要求精确斜杠路径、逐字原文、唯一上下文及同字段顺序应用。
- 结构化模型返回先写入既有 STORY 的 RUNNING 检查点，再尝试应用。失败记录具体的修改序号和安全原因，保留补丁，不提交工作副本。
- 对缺失位置、原文未命中或重复、替换内容/依据缺失及长度问题提供独立提示。重叠命中的判定和 UTF-16 字符长度与现有 TypeScript 服务端规则对齐。
- 恢复时收到过的有效补丁直接复用；无效补丁在用户显式继续时携带上次机械问题重新生成。没有添加新的自动模型修复循环，正常调用次数和人工采用边界保持不变。
- API 任务失败摘要优先读取已持久化的 STORY 具体错误；历史没有具体错误的记录保持原有阶段说明，不编造原因或改写旧任务。

# 审核用语与失败修正入口

范围：定制类脚本局部更新。审核意见使用普通中文，审核不通过时提供明确的“按审核意见修正”入口，仍经已有范围预览主动执行。原脚本、人工采用及当前路径隔离保持不变，不自动调用模型。

1. API 展示边界转换已知字段名为正文、故事段落、故事结构说明、产品外观等中文，保留原问题、引文与建议；同步候选与工作流详情。补充可选审核状态和结构化问题供前端说明下一步。
2. 根级 `structure` 是叙事结构说明正文，纳入精确修改白名单、Worker Schema 和候选编辑字段，并与概要、正文及篇章按需同步。`settings.structureMode` 等才是类型配置，不在可改范围。兼容历史已有 `story.structure`，不生成缺失字段、不改身份、创作类型或时长。首次修复误将根级说明当作类型，后续以实际任务冻结数据核对并纠正。
3. 审核失败的旧任务保留；新局部更新只在同项目/路径/脚本、同信息卡来源及同基线下携带失败候选和审核意见，生成新的修改候选再审校。旧任务的审核错误不得通过重复恢复成功检查点而原样失败；不增加自动返修轮次。
4. 前端明确失败原因、建议和下一步，在候选内提供修正入口并沿用已有范围确认。未通过候选只读核对，通过后继续人工微调并保存，不放开失败稿直接采用。
5. 验证中文展示、旧字段兼容、反馈作用域、失败后修正、旧任务保留、人工确认、类型构建、Worker 及数据库检查；默认受控测试，无活动任务时更新本地服务，真实付费修正由用户主动触发。

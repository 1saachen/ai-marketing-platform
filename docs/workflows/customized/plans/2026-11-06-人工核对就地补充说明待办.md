# 人工核对就地补充说明待办

2026-11-06 收尾记录。用户要求先提交并推送当前成果，下一次继续本功能；本文记录讨论方向，功能尚未实现，不把输入框或联动提交描述为已上线。

## 当前问题

资产局部更新已经由模型判断必要范围，但发现信息卡冲突时会暂停。当前“需要人工核对 / 下一步”仍主要罗列问题，用户需要回信息提炼编辑；部分提示带字段路径，且下一步重复问题，没有就地说明入口。

## 下次继续的方向

- 在当前人工核对区域提供“补充说明并重新判断”，让用户用普通语言解释本次修改，例如只改产品杯身配色、保留其他已确认规格、容量不确定且本次不展示数值、背景色保持原设计。
- 模型先整理修改建议并展示前后差异，由用户确认后应用；商品事实修正仍须写回唯一确认的信息卡，不能只改资产而继续保留互相冲突的事实。
- 本次制作要求与商品事实分开：不展示某参数不等于改写参数事实；未知规格不编造，未重述全部规格不自动等于全部规格失效。是否阻断应由模型结合实际修改及引用范围判断。
- 复用原信息卡确认边界、当前路径与多方案来源规则、任务/租约/检查点，不增加另一套事实或任务状态。上游确认后仍明确展示受影响脚本及资产；导航或普通保存不自动付费生成。
- 旧失败任务保留原冻结输入，新说明使用新的明确任务或版本化修正机制；旧回调不能覆盖新结果。保留人工成果及已有图片、视频。
- 统一提示用语，去除字段路径，避免在“下一步”重复整段问题。交互位置、具体确认动作及同步顺序在实施前核对现有组件和契约。

## 开始时核对

先查 Git 状态及本地运行版本，阅读根规则、Web/API/Contracts/Worker 规则与定制类指南；沿用 `develop-workflow-node`。已有本地服务及用户项目保留，不重新复制线上数据，不自动继续失败任务。默认使用受控测试，真实付费生成另行明确授权。

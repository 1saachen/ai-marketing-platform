# 多方案共用当前信息卡

用户确认：普通方案切换继续使用同一资料来源下当前确认的商品信息，各方案独立保留创意与已生成结果；版本树显式回看读取当时的快照。保存信息不自动调用模型。

## 数据与边界

- 复用 WorkflowRun、WorkflowNodeState、WorkingArtifact 及确认快照，不新增表。以同项目、CUSTOMIZED 工作流的根路径限定信息卡来源家族，排除其他项目、其他根路径、未确认编辑和失效内容。
- 导航只保存 CURRENT / HISTORICAL 查看意图；不推进业务 revision、不复制或改写脚本和视频。兼容旧客户端及无查看意图的历史读取。
- 当前信息头来自真实确认记录；复制或采用共享来源不被当成新的商品信息确认。工作区、影响预览、任务冻结和保存都使用同一个已确认来源。
- 各方案正文只在用户主动执行更新并保存候选后原位提交，依赖记录实际消费的信息卡 artifactId + revision。其他方案保持旧正文并提示待更新。
- 制作节点检查脚本是否消费当前信息，避免越过脚本更新；旧视频保留预览下载。人工信息编辑从当前信息卡建立隔离草稿。

## 实施与验证

1. 共用来源解析、查看意图契约与普通/历史导航。
2. 信息卡与脚本工作区、预览、任务、保存及制作依赖联动。
3. 数据库受控验证两轮信息修改、A/B/A 切换、刷新、历史回看、未确认草稿、家族隔离、候选过期和失败恢复；不得投递真实模型任务。
4. 相关 Contracts、API、Web 测试、类型、构建、格式检查；无活动任务时更新本地 API，核实方案二实际更新预览。浏览器不可用时如实记录限制。

## 实施记录

已接入共享确认来源、普通选择与历史回看的查看意图、工作区待更新投影、脚本候选来源冻结和采用、制作依赖校验及方案卡片提示。未增加数据库表，未改写兄弟方案正文；导航不提交业务 revision。

本地现有项目的三个方案已通过真实 HTTP 接口验证，受控数据库测试覆盖连续来源变化与过期候选保护。实际命令、结果和未验证范围见[验证记录](../evidence/2026-11-06-多方案共用当前信息卡验收.md)。

同日补充：脚本局部更新弹窗展示工作区返回的全部待更新方案，明确区分当前方案与其他方案、本次执行范围；当前方案是否需要处理以最新预览为准。单方案局部更新失败按实际检查点说明未完成阶段，不再使用批量创作的“部分脚本”文案；旧通用文案在读取边界兼容，不改写历史记录。局部更新的进度、候选与恢复仅在所属方案展示，不混入整批创作的全局提示。

候选等待状态补充：复用现有单任务只读接口，展示真实排队/改稿/审校/候选状态、步骤和已等待时间。候选未成功时明确禁用保存的原因；完成后自动切换为可保存，不覆盖用户已编辑的候选。剩余时间未知时不编造倒计时。无接口或数据库变更，不改变人工采用、业务 revision、下游依赖和原脚本保留规则；验证恢复、轮询失败、迟到响应、窄屏和关闭后台继续。

改稿校验补充：模型接口成功后、应用修改前先保存返回的补丁至既有 STORY 检查点；对不存在的修改位置、原文未命中/重复命中、空依据和长度错误记录可读原因。请求 Schema 限制为冻结脚本实际可改字段，明确使用斜杠路径。成功收到但尚未应用的有效补丁在恢复时直接复用；无效补丁由用户显式继续时携带机械问题重新生成，不增加自动模型返修轮次。保持精确唯一匹配、服务端复核、未改内容和人工采用边界；不放宽成全局替换或模糊匹配。验证无效结果保留、断点恢复、失败后继续及 Python/TS 校验一致性后，仅在无活动任务时更新本地 API 与脚本 Worker。

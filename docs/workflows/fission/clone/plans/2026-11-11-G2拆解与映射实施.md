# G2 深度拆解与元素映射实施

日期：2026-11-11。依据用户继续实施 G2 的指令与[完整计划](2026-11-11-爆款复刻真实链路实施计划.md)。本文明确本次纵向切片的实现与验收边界；检查结果另记 evidence，不将待执行内容写成通过。

## 范围与提交点

保持上传素材 → 深度拆解 → 元素映射 → 成片生成四节点。G1 当前工作区继续使用，G3 成片生成维持不可用。本轮不迁移日常数据库、不启动真实付费消费者、不实现原音分离、转录或声音克隆。

| 节点     | 直接来源                                                                                | 草稿                                                                            | 确认产物与提交边界                                                                     | 下游                 |
| -------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | -------------------- |
| 深度拆解 | 当前 Run 的 `clone-input`，精确 artifactId/revision/contentHash，冻结商品事实与文件身份 | 同一 `WorkflowNodeState(CLONE_ANALYSIS)`，独立人工编辑，带 baseAnalysisRevision | `clone-analysis`；完整任务成功且校验通过自动提交；人工编辑明确保存提交，取消保留确认版 | 真实引用该报告的映射 |
| 元素映射 | `clone-analysis` 与商品事实所在 `clone-input`，以及当前项目资产精确版本                 | 同一 `WorkflowNodeState(CLONE_MAPPING)`，来源、逐元素绑定与结构锁定             | `clone-mapping`；全部必换产品和替换目标有效后人工确认                                  | 后续成片生成         |

普通保存、导航、匹配建议与文本核对均不推进业务 revision。同内容提交不增版；已确认来源变化沿真实依赖标记已有下游待更新，不制造空产物或自动创建任务。

## 契约与有限能力

`packages/contracts/src/fission-clone-analysis.ts` 是报告、映射、任务与内部快照的唯一字段定义。发布 JSON Schema 与 fixture，Python 直接消费发布 schema 并覆盖语义一致性验证。

- 报告：结构、创意、产品、纵向镜头时间线、音频、视觉六维，包含稳定阶段/镜头/元素 ID、整数毫秒区间、阶段占比、证据种类和置信度。阶段与镜头连续覆盖原片，元素双向引用一致，缺项有原因。
- 当前仓库只具备抽帧图像理解适配基础。本轮真实适配使用受控 FFmpeg 采样和共享 Responses 结构化图像调用；画面抽样不能证明所有逐帧事件或镜头边界准确，报告必须表达局限。
- 音轨存在性来自媒体探测；口播/BGM/音效/转录语义为 `UNASSESSED`，不以未分析冒充未检测，不输出伪造节拍、静音区间、转录或音频元素。无轨道保留、烧录内容可靠提取及音色能力时，相关 KEEP 确认被阻断。
- 映射按元素实例配置，所有产品必换。目标为精确资产版本或明确内容/风格；文本内容策略与表现策略分开，锁定属性与允许变化属性不能冲突。结构锁定由确认报告派生并校验。
- `SMART_MATCH` 本轮使用候选资产元数据给建议，明确没有核对候选图像，不虚构评分或视觉一致性结论；采用前可查看真实文件。`VALIDATE_KEEP_TEXT` 独立显式发起，核对目标商品事实与原文字，证据绑定来源和内容哈希，确认时不调用模型。

## 任务与文件

新增复刻领域 Task / Step / FileHold，复用现有 Outbox、项目→Run 锁、StoragePort 和 WorkingArtifact 提交。队列显式为 `fission.clone.analysis.requested`，小消息 runId 表示 taskId，真实 workflowRunId 从受保护 claim 返回。Worker 只访问所属任务文件，不接收任意读取地址。

创建冻结不可变来源与目标 revision，同幂等键不同输入冲突。claim、续租、进度、检查点、complete、fail、cancel、原快照 retry 和有界过期恢复保持 attempt/租约校验。完整分析结果与终态同事务提交；映射建议只按冻结草稿 revision CAS，冲突保留待采用。分析完成时保留并发人工草稿。PAUSED 不等于取消，退出后的后台任务仍可合法完成。

上游确认与依赖它的活动任务互斥，允许独立草稿继续编辑。暂停升级为所有已存在节点草稿 revision 的快照，兼容仅有 G1 输入时的旧请求；恢复提升所有草稿 revision，拒绝旧编辑代次请求。

精确映射资产先经专用准备入口读取合法版本、核实文件身份并登记当前 Run 的文件引用，再进入草稿。暂存映射文件与任务 hold 接入通用孤儿/存储清理、输入移除和项目删除门禁；不把 JSON 中的 fileObjectId 当成自动保活。

## 前端复用与验证

复用 `CloneRealWorkspace` 单一画布和 `clone-prototype.css` 六维报告、纵向镜头卡、映射双栏区域；历史 Mock 组件保留显式演示。复用 `WorkflowNodeFooter`、`WorkflowRunProgress`、工作流编辑动作组件、`CloneDialog`、真实资产预览与选择。轮询合并服务端任务/产物，不能覆盖未保存编辑或拉回节点导航。

必须检查：契约边界、完整报告/非法时间引用、全部产品必换、精确资产版本与跨项目拒绝、自动提交与重复完成、两轮来源变化、来源/目标版本冲突、任务取消/过期/旧 attempt、PAUSED 完成、建议 CAS/采用、文本证据过期、多节点暂停 fence、文件 hold 与清理。

无付费验证使用独立数据库与显式 Fake Provider 测试流程，不能把其报告称为真实模型结果。浏览器覆盖空/运行/失败/成功/待更新、人工编辑取消与提交、刷新恢复、映射确认和关键宽度；实际命令、截图和未验范围写入证据。真实供应商质量验证及日常环境上线继续单独记录。

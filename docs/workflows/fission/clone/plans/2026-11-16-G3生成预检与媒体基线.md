# G3 生成预检与媒体基线

日期 2026-11-16。接续 [G2 记录](../evidence/2026-11-11-G2拆解与映射实现验证.md) 与 [真实链路计划](2026-11-11-爆款复刻真实链路实施计划.md)。

本轮补齐 G0 中阻塞 G3 的受限方案和可验证执行基础。`CLONE_GENERATION` 消费同一项目、同一爆款复刻 Run 已确认的 `clone-mapping`、`clone-analysis`、`clone-input` 精确引用。预检采用正常登录权限，锁内校验确认版本和素材引用，生成结构化内部计划并返回安全摘要。预检是只读操作，页面上的成片生成按钮由后续任务接入开放。

- 首条路径采用 Seedance 2.0 系列参考图生视频，一批一条，最多四个镜头，最终时长 1–15 秒。每镜头的供应商请求时长最少 4 秒、最多 15 秒，合成按锁定帧区间截取，接受全部镜头硬切和静音的显式选项。选定的商品必须逐项绑定当前项目的确认图片版本，场景可用明确文本替换。人物、字幕、音频、贴纸和其他轨道或转场策略须在创建供应商请求前阻断。该路径的供应商质量待授权实测。
- 输入时间为整数毫秒。帧计划从绝对边界按有理帧率四舍五入，冻结阶段、镜头与钩子/转化区间。固定输出 24 帧/秒、720p、16:9 或 9:16。合成拒绝覆盖不足、错误画幅或不完整解码，不做循环、补帧延长或变速。生成源片只使用目标商品图片，原参考照片或视频不传给渲染接口。
- 预检路径 `POST .../fission-clone/generation/preflight` 复用 G2 门禁与锁。Worker 媒体代码读取共享 JSON Schema；本地 FFmpeg 样本验证分数帧率、短镜头、硬切、错画幅、素材不足和完整解码。
- 后续任务调度复用 Outbox、作用域、租约与保活。创建供应商任务前要持久化创建意图，已知 ID 只继续轮询，未知结果必须核查。候选只在完整质量和媒体校验后提交 `clone-video:<variantId>` 与 `clone-batch:<batchId>`，直接记录所消费的映射版本。后续报告/映射更新只标旧结果待更新，归档和导出独立消费已提交精确版本。预检阶段无草稿、任务、文件写入和数据库迁移。

## 首条路径的能力与证据

供应商协议于 2026-11-16 核对。每条成片最多四个供应商创建请求，预检返回每个镜头的供应商秒数和合计。上限按镜头需求得出，费用与账号配额要以实际授权和部署配置为准。[火山方舟创建视频生成任务 API](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)

| 能力           | 实现边界                                                                                                                         | 当前证据                                                                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 参考图生视频   | Seedance 2.0 系列参考图模式。请求 4–15 秒，720p 的 9:16 或 16:9。仓库限每镜头最多 4 张图、单张最多 4 MiB，校验尺寸与精确文件哈希 | 官方协议核对，MockTransport 验证请求字段、图片绑定、下载与恢复。实际部署模型及生成质量未验                                                 |
| 识别和音轨     | G2 提供抽帧视觉报告。静音模式发出关闭生成音频的请求，合成只取画面。口播、BGM、字幕、人物原样保留等不进入该路径                   | 实际 FFmpeg 测试输入含音轨，输出仅有 H.264 视频轨                                                                                          |
| 短镜头和时间线 | 镜头锁定原绝对边界，生成足够帧后截取头部，固定硬切。按有理数验证时长、帧数和 PTS                                                 | 720p、24fps 的双镜头样本输出 72 帧，在索引 36 切换颜色。独立 30000/1001 合成样本保留 1 帧镜头并通过 91 帧逐帧 PTS 检查。其他转场在预检拒绝 |
| 失败及合格提交 | 原子发布文件前验证时长、尺寸、帧率、帧数、音轨、编码与完整解码。模型语义审片和工作副本提交仍需接入                               | 短输入、错误尺寸、损坏容器均未产出文件。测试未评价商品外观、镜头语义或可投放性                                                             |

FFmpeg 链路使用 `fps`、`trim` 和 `concat`。按计划写回统一时间基，避免每段时间独立取整造成累积偏移。[FFmpeg 滤镜文档](https://www.ffmpeg.org/ffmpeg-filters.html)

## 后续任务恢复边界

| 已保存的镜头执行状态     | 下一步                                                                         |
| ------------------------ | ------------------------------------------------------------------------------ |
| `NOT_STARTED`            | 持有当前租约时原子登记 `CREATE_PENDING`，再向供应商发一次创建请求              |
| `CREATE_PENDING`         | 若未记录供应商任务 ID，阻断再次创建并核查，包括在发出请求前后崩溃的情况        |
| `CREATED`                | 使用已保存的供应商任务 ID 继续轮询或下载。接口错误不能清空已知 ID              |
| 已保存验证通过的镜头文件 | 合成或审片失败时从保存的镜头文件恢复，保持来源与计划哈希                       |
| 合成与质量均通过         | 在当前来源和租约下原子提交批次及成片工作副本。失去租约的写回不能替换已确认结果 |

前 3 行已在 Python 适配层验证状态顺序与重复创建阻断，数据库中的创建意图、文件检查点和整批发布仍待接入。真实小样应先覆盖有目标商品图的无人物样本，再单独评估口播、烧录字幕和多版本差异要求。后三类当前由不支持的模式或元素门禁阻断。

## 验证结果

- `pnpm --filter @ai-marketing/contracts test` 通过 396 项。包含发布 schema 与代码一致性、分数帧率共用边界、零帧、非法模式和缺字段。
- 把现有 53 个迁移应用到单独启动的 PostgreSQL 16 隔离库。运行 clone 目录与环境校验 Vitest，共 64 项通过。包含 G1/G2 回归、预检精确版本、陈旧状态、跨项目/Run、无写入检查及真实媒体入库校验。旧测试库端口未监听，验证改用独立库，运行后已关闭独立进程。
- `pnpm typecheck`、API 生产构建、定向 ESLint、Prettier、`git diff --check` 通过。
- 在生成模块运行 `uv run --frozen pytest -q` 与 `uv run --frozen mypy src`，15 项通过，4 个源码文件通过类型检查。媒体用例实际执行本地 FFmpeg/FFprobe。

本轮没有 Web 改动。真实供应商调用、运行队列、质量审片、成片发布及归档尚未验收。

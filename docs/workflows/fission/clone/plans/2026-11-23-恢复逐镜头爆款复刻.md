# 恢复逐镜头爆款复刻

## 范围

爆款复刻沿用上传素材、深度拆解、元素映射、成片生成。完整拆解提取原片结构和节奏，以及逐镜头的切点、景别、构图、运镜、主体动作和证据帧。新批次逐镜头生成目标商品画面，沿锁定切点合成。局部换道具使用独立的局部元素替换工作流。现有复刻的原片编辑任务和交付继续按其冻结方式恢复。

本次复用现有四节点界面、完整分析指令、逐镜头生成和审片能力。音频语义、字幕还原、非硬切转场与已发布成片局部返修不在范围内。

## 来源与提交

- 深度拆解消费同项目、同 Run 的确认 `clone-input` 引用（`artifactId + revision + contentHash`）。新任务使用完整六维和镜头动作分析指令，已排队任务保留原指令版本。成功后自动提交 `clone-analysis`，人工改动按现有草稿和确认边界处理。
- 映射仍引用精确输入和拆解版本，通过人工确认提交 `clone-mapping`。商品继续绑定同项目目标图片版本。历史道具保留为镜头参考；若旧草稿已有道具替换，显式改为保留后才能用于新批次，草稿和已确认内容不自动改写。
- 生成预检与新建共用逐镜头计划。冻结输入、报告、映射引用、图片版本、帧时间线和每镜头的运镜、构图及相对时间动作证据。预检按实际逐镜头请求秒数计量。商品名称和商品事实可按需提供。
- 沿用批次规划、独立审片、首条验证、任务检查点、租约和 Outbox。整批通过审片后提交 `clone-video:<variantId>` 和 `clone-batch:<batchId>`。旧版本照常读取、下载和归档，上游实际确认变化时才按既有依赖标记待更新。
- 无数据库迁移。先部署兼容空商品资料及两种历史模式的生成 Worker，再更新 API 和 Web。

## 验收

- 预检与新建都冻结逐镜头计划；相邻镜头各自消费景别、运镜、构图和动作约束，合成保持锁定总时长和切点。
- 商品文字为空、场景或人物保留、历史道具保留都可生成。历史道具替换给出明确处理方式。已创建的原片编辑快照仍可以解析、重试和恢复。
- 隔离验证两条与规划批次、来源变更与旧结果、重复创建、任务失败和恢复；校验 Web、API、Contracts、Worker，以及镜头证据界面和生成确认。真实模型画面验收需单独授权。

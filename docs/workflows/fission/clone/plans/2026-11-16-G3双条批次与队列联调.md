# G3 双条批次与队列联调

成片节点沿用同项目、同 Run 的已确认映射、拆解和输入，冻结三者的 artifactId、revision、hash 及商品图片的精确版本。每条仍按现有静音硬切规格生成，选择一条或两条并确认合计渲染秒数。数量是本次执行设置，由预检和任务快照保存。页面和项目导航复用现有草稿与 Run。

双条创建在 Run 锁内登记一个协调记录和两个独立执行任务，事务内写文件引用与两条 Outbox。使用复合外键约束项目、Run 和父任务。协调记录保存已完成的同步规划和发布状态，只派发需要供应商的条目。单条任务及已有产物保留现有键和访问路径。每条执行阶段、attempt 和供应商检查点独立。

首次发布需要两条媒体校验和审片均通过。最后一个通过的回调在 Run 锁内触发协调提交，服务端复核两条冻结来源和文件，原子提交两个视频和一份引用精确成片 revision 的清单。中间成功只显示等待整批完成。显式重试只更新失败条目的任务和 Outbox。整批取消清理两条暂存引用，遮断迟到回写。部分完成时可以修改来源，旧批次必须先取消才能用新来源创建，过期批次不可续做。

隔离验收使用真实 RabbitMQ、Outbox、API、Worker 消费、PostgreSQL、FFmpeg 和模拟供应商。关键用例包括真实派发、一条通过一条故障、失败条目复用检查点、跨项目拒绝、重复确认、旧租约、刷新恢复、部分结果无交付、全部通过后原子发布。真实模型差异化、付费小样、局部重做、音轨、ZIP 与 20 条规模留在后续阶段。

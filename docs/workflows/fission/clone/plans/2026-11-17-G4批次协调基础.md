# G4 批次协调基础

成片节点继续消费当前项目和 Run 中确认映射、报告与输入的精确工作副本版本。父任务沿用已冻结的计划、供应商配置和条目数量。子任务保留自己的镜头和审片检查点。批次在全部条目校验通过后原子提交视频及清单。

这一阶段先扩展批次存储和协调能力。数据库允许批内位置 1–20，保留项目和 Run 的复合外键、位置唯一约束及已有记录。幂等响应与最终发布核对冻结数量、连续位置和父子快照。前端和 HTTP 创建契约此阶段继续提供 G3 一至两条能力。G4 对外开放还依赖全批差异化规划、逐条计划冻结和可见差异的质量验证。

在隔离 PostgreSQL 应用迁移。使用内部构造的 20 条冻结记录和模拟检查点验证部分失败时无交付、仅失败条目恢复、整批原子提交和清单的精确 revision 引用。回归原有一条及双条。迁移不改现存行，无需重算快照指纹。正式发布前另做迁移演练和 20 条真实质量验收。

隔离 PostgreSQL 应用全部 56 个迁移。复刻 API、媒体及环境配置共 69 项测试通过。20 条用例中，19 条成功且 1 条失败时保持无交付。失败条目重试复用已保存镜头，其余条目未重新派发。最后一条通过后提交 20 个视频工作副本和一份引用各自 revision 的清单。现有真实单条快照也能在新迁移下加载并归档。

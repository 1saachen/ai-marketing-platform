# G3 真实模型小样验收

G2 拆解消费同项目、同复刻 Run 的确认输入。人工确认映射后，G3 冻结映射、报告、输入和图片版本，使用既有任务、Outbox、镜头检查点和审片门禁。只有媒体与审片通过才提交成片与交付清单。样本验收在隔离项目中执行。

## 首轮请求

使用本地自制的 6 秒、720×1280、24 FPS 双镜头静音参考片和一张 576×576 的目标包装 PNG。原片展示蓝色瓶型，目标图是带青绿色横带的橙色长方盒。均无人物、字幕或真实品牌。样本位于工作区临时目录 `.tmp/clone-g3-provider-smoke/`。

| 阶段 | 请求范围                                                                    | 检查项                                                                           |
| ---- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 拆解 | 一次 Ark 多模态 Responses 请求，最多 8 个采样帧及 8192 个输出 token         | 判断蓝色瓶型在两个镜头可见，报告与已知切点对照。音频语义为 `UNASSESSED`          |
| 映射 | 人工绑定精确商品图片版本                                                    | 原片商品必换。保留阶段、镜头顺序和画面时长                                       |
| 成片 | 一条 720p 静音硬切成片，最多两次 Seedance 2.0 创建，合计请求时长不超过 8 秒 | 预检后才发起。成片按冻结计划校验，人工检查橙色外形和青绿横带、原商品是否残留     |
| 审片 | 一次 Ark 多模态 Responses 请求，最多 4096 个输出 token                      | 对照人工审片，记录通过、告警、失败和证据。只有完整通过才产生可预览、可下载的交付 |

建议首轮总预算上限 15 元。方舟公开价中 Seedance 2.0 标准版无输入视频的 720p 示例为 16:9、5 秒约 4.97 元，同类规格 8 秒约 8 元，另计两次视觉调用。该价格为估算，实际用量以账号和供应商回执为准。[方舟模型定价](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh)

首轮候选模型为 `doubao-seed-2-1-pro-260915` 与 `doubao-seedance-2-0-260128`，实际使用已开通的型号或等价部署，开通情况待核对。现有本地配置有方舟连接项，复刻专用的三个模型配置未指定。隔离运行时设置任务与分析调用尝试次数为 1。遇到模型权限、预检预算或质量阻断时停在该节点。[方舟模型列表](https://docs.volcengine.com/docs/ark/model-list?lang=zh) · [Seedance 2.0 模型说明](https://docs.volcengine.com/docs/ark/seedance-2-0?lang=zh)

## 执行前检查

- 首轮请求须由用户明确授权范围和预算。验收仅向方舟发送自制样本的帧、目标图片和相应提示。实际业务素材另行指定和授权。
- 在隔离 API 和 Worker 环境注入配置，使用独立 PostgreSQL、RabbitMQ、两个 Worker Token 和临时存储。应用当前迁移后走正常项目、任务和回调入口。
- 本轮提前核对了 Seedance 2.0 公开协议。图片通过 `reference_image` 传入，提示按 `图片1` 等序号引用。已移除仅 Seedance 2.5 系列支持的 `omni_reference_task_type`。[创建视频任务 API](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)
- 保存采样和人工审片结论、用量和交付状态。授权后实际测试结果另写证据记录。多条的可见差异、音频和字幕策略另设样本。

## 已执行的本地验证

FFprobe 确认参考片为 6 秒、144 帧、H.264 单视频轨。FFmpeg 完整解码通过，第 71、72 帧的哈希不同，与制作时的 3 秒切点一致。使用样本图片和本地计划编译出两个 4 秒的 Seedance 请求。真实 FFmpeg 抽帧结合模拟 HTTP 验证了审片的 7 张输入图片和失败判定。Worker 的 16 项测试和 mypy 类型检查通过。

## 拆解复验修正

[真实复测](../evidence/2026-11-17-G3真实小样复测.md)显示，提高输出上限可得到结构完整的报告，但原有三张等距图不足以确认 3 秒处的切换，目标商品资料还被写入原商品描述。复刻拆解 Worker 在冻结的参考视频上补充一次有界画面变化检测，为选中的候选点提供前后帧。模型根据画面判断切点与原商品，目标商品资料在元素映射时继续从确认输入读取。

沿用共享报告契约、原输入 revision、自动提交和下游 freshness 规则。媒体测试覆盖同一参考片的 3 秒变化、采样上限和无明显变化的片段，HTTP 测试检查实际送入拆解的证据及商品资料隔离。通过后用同一小样复验，记录镜头、商品及预检结果，再判断是否满足真实成片条件。

2026-11-17 本地验证中，实际 FFmpeg 为原小样抽取了 0、2.85、2.9、3.05、5.8 秒的五张图。隔离 API 应用 55 个迁移，通过 RabbitMQ 调度更新后的分析 Worker。模型替身核对请求后返回测试报告，API 保存报告第 1 版并确认映射第 1 版。生成预检返回一条 720×1280 静音硬切成片，输出 6 秒，两个镜头各请求渲染 4 秒。复刻拆解 Worker 的 50 项测试和类型检查通过。

同日的真实复验识别出 3 秒切点及两个镜头中的原商品，完成映射、生成、审片、发布与 API 下载。[真实成片验收记录](../evidence/2026-11-17-G3真实小样成片验收.md)

# G2 镜头内动作拆解

目标是复用参考视频中可观察的镜头执行方式，包括主体动作、相机运动、人与商品的接触、商品朝向和遮挡。用当前项目的目标商品完成元素映射。刚才的四秒实拍在原采样规则下得到 0、1900、3800 毫秒三个采样点，整个拿放过程无法逐步核对。现有报告用自由文本描述镜头，成片计划也只继承三段文字。

## 实现范围

- 爆款复刻的直接上游依然是当前项目和 Run 已确认的 `clone-input` 及其 revision。新建分析任务冻结拆解指令版本。新规则以 500 毫秒为基础间隔，在现有总帧数上限内覆盖镜头内变化，同时保留疑似切镜的成对证据。历史任务沿用原规则。
- 相机、主体、接触和商品姿态在同一镜头的动作区间内记录，区间引用实际采样时间。每个镜头明确区分观察到动作、未见动作和证据不足，摘要保留起始和结束画面状态。模型使用有时间序列的图片，证据缺失时记录限制。Worker 与 API 校验顺序、范围、状态和证据。音频边界沿用当前能力。
- 新增内容随现有 `clone-analysis` 提交，保持现有人工草稿、自动提交、revision 和来源失效规则。元素映射仍消费当前确认报告，锁定原有阶段和镜头范围。成片计划继承同一份已确认动作观察，区间和证据统一转为镜头相对毫秒。审片在首、中、尾外按动作证据时点抽取成片帧，API 用同一规则校验证据编号。既有布景差异化与交付规则继续适用。
- 报告在现有镜头时间线内展示动作与可跳转证据。人工编辑可修正动作文字和区间，提交时校验引用证据仍在区间内。旧报告和旧成片快照允许缺少新增字段，可继续读取和恢复。无需迁移数据库。部署时先更新两个兼容新旧契约的 Worker，再更新 API 和 Web。

## 验收

本地用刚才的四秒实拍核对采样时点是否覆盖提起、移动、落桌和松手。用契约及 Worker 测试覆盖可观察动作、证据不足、过界证据、历史数据、生成请求与审片对动作的实际消费。检查相邻镜头边界、媒体参数、幂等及 Web 报告。真实模型拆解与复刻质量仍需另行试片。本轮不调用付费模型。

## 本地结果

四秒实拍实际采样从 0、1900、3800 毫秒增加为 0、475、950、1425、1900、2375、2850、3325、3800 毫秒。工作区类型检查、Web 构建、Contracts 412 项、复刻 API 及环境配置 76 项、拆解 Worker 70 项和生成 Worker 40 项通过。两个 Worker 的 mypy 通过。新报告浏览器验证使用本地组件和测试数据，覆盖 1920、1440、390 像素、证据跳转、草稿文字与区间编辑、证据不足和历史报告。尚未在新规则下调用真实拆解模型或生成视频。

## 提示词证据校正

小瓶实拍的两次模型拆解都识别出了主要动作。抽帧报告在首帧已见手握瓶盖时，额外写了手入画。直传试验把松手区间拆得更接近原片，同时给出了偏晚且过于具体的触桌时间。两份报告对落桌后瓶身朝向都描述得偏粗。直传原稿还有四个动作时点未列入所属镜头的证据列表。

平台自动分析任务使用已确认的 `clone-input`，新任务冻结提示词版本 3。模型按首个和最后一个可见状态写开场与收尾，用可观察的相邻帧区分过渡和已发生的状态。持握、下放、接触、扶稳、松手按可见证据描述，受遮挡的接触和脱离用判断区间。商品哪一面朝向镜头应有可见的文字布局、图案、轮廓等依据，并在收尾状态记录。Worker 在校验前汇总镜头自身与动作已引用的证据时点，仍逐个对照本次实际采样。

沿用现有自动采样、模型调用和报告确认流程。旧任务按冻结版本恢复。发布此版时先更新拆解 Worker，再更新创建新任务的 API。当前验证用本地回放和模拟响应；直传 MP4 属于单独的试验记录。

四秒实拍重新本地采样，以过去的报告模拟模型遗漏重复时点。版本 3 恢复了实际引用索引，动作内容保持相同，未采样证据仍被拒绝；版本 2 沿用原校验。复刻 API 隔离数据库 76 项、Contracts 412 项、分析 Worker 77 项、工作区类型检查和 Worker mypy 通过。

# G4 差异化规划

成片生成消费同项目、同 Run 已确认的输入、报告、映射及其精确版本，继续冻结每条的镜头、相同帧时间线及目标图片。当前静音硬切仅支持商品和场景。三至二十条时，规划只能使用确认映射给场景元素声明的允许变化项。原商品替换、目标图片、商品事实、锁定特征和时间线都沿用预检计划。至少存在一项场景变化才接受批量预检。现有一、两条入口保持兼容。

三条及以上创建异步协调任务，提前分配全部 variantId 并冻结规划模型。Worker 走原生成队列和租约。先生成精确数量的场景方案并保存检查点，再交由单独的模型请求检查视觉差异和冻结约束。通过后 API 在一个事务中校验来源、生成逐条快照并派发 Outbox。暂时故障重试从已保存的规划继续；质量拒绝停止派发。全部成片通过现有逐镜审片与精确版本校验后，发布视频和清单。规划及审片均需校验场景约束，条目重试不重新规划。

当前正式入口由 API 根据规划模型配置返回可选数量。前端沿用现有预检、预算确认、批次条目和取消入口，增加无子任务时的规划进度、失败重试及批次取消。规划调用在 Worker 中完成，服务端事务不直接调模型。

迁移：沿用已扩大至 20 的任务位置约束、已有父子任务和检查点表。已有单条和双条快照无需重写。用模拟供应商及隔离库验证无场景变化的请求拒绝、两级规划、草稿恢复、重复及迟到回调、零子任务时取消、准确 20 条和原子发布。另用真实付费样本验证画面差异及成本。

整批下载从已提交的批次清单解析精确的视频工作副本和文件 SHA-256。页面使用清单 revision 和 hash 生成只读下载链接，浏览器直接接收流式 ZIP。包内包含有序 MP4 及 `manifest.json`。旧交付可按原版本下载，清单标明 freshness。预检失败、部分成功或无清单的批次没有下载入口；导出无需新任务或模型调用。

## 真实验收后的逐镜头规划修正

首轮真实批次把同一段含整片切换的场景描述交给两个独立镜头，导致第二镜头再次从远景开始。[十条真实批次与画面对照](../evidence/2026-11-17-G4十条真实批次验收.md)

新建批次在父任务冻结规划契约版本。每条变体选择一个映射中的场景元素和允许变化维度，并给该元素实际覆盖的所有镜头分别填写 `shotId` 与可从首帧呈现的静态场景要求。API 校验镜头归属、完整性和顺序，再按 ID 写入单个镜头的执行快照。规划与镜头渲染的模型输入只描述本阶段所需内容，镜头切换与时间仍由冻结时间线和 FFmpeg 决定。规划独立审查继续负责判断语义差异与场景可执行性。

旧批次按其冻结版本读取检查点和已派发镜头，一至两条的路径沿用原快照。该调整无需数据库迁移。发布时先更新生成 Worker，使其同时识别两种规划契约，再更新 API 接收逐镜头规划的新批次。隔离测试复现两个镜头收到同一整片安排的输入，验证新批次拒绝旧格式、缺失或错绑镜头，正确快照发布与恢复须继续通过。真实供应商画面效果单独记录。

本地验证覆盖同一参考片的 3 条批次。由正式成片页面发起，隔离 PostgreSQL、RabbitMQ、API 和生成 Worker 完成规划、投递、FFmpeg 合成、发布和窄屏刷新恢复，共 4 条已投递消息。供应商替身核对了 6 个渲染请求，各自仅包含对应镜头的场景安排。全程未调用付费供应商。

共享契约 4 项、API 隔离测试 71 项、Worker 21 项及类型检查通过。API 另覆盖 20 条逐镜头规划的重领、原子发布，以及历史批次格式恢复。工作区构建、类型检查、变更文件 ESLint 与格式检查通过。

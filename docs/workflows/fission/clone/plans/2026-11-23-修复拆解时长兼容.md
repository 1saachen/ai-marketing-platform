# 修复拆解时长兼容

## 现场与范围

线上同一份已确认原片的 SHA-256 一致。API 媒体探测返回容器时长 4.042 秒，视频轨实际为 4.000 秒、96 帧。两个复刻 Worker 均读取到 4.000 秒。拆解三次达到 85%，结果与冻结输入时长不一致，检查点未保存。Worker 吞掉回写冲突后停止心跳，最终显示租约过期。

修复涉及上传媒体探测、深度拆解回写和成片原片归一化。四节点、独立局部替换、已确认来源和历史成片保持原有版本语义。

## 规则

- 新上传优先使用可用的视频轨时长，缺少时回退容器时长。拆解按相同顺序探测。
- 拆解仍读取当前项目和 Run 的已确认 `clone-input` 精确版本，并验证原文件哈希和尺寸。历史快照的时长差距至多一帧（按 24 fps 取整上限 42 毫秒）时，报告使用冻结时长。采样范围限制在真实视频与锁定时长的交集。更大的差距在调用模型前明确失败。
- 有效任务的报告保存收到明确的结果校验失败时，尝试在当前租约内写终态。取消或过期以后沿用原租约限制。
- 历史冻结原片在逐镜头参考归一化时若恰好只差最后一帧，可用末帧补齐。其它生成媒体维持精确校验。原片身份、镜头顺序和提交边界沿用当前规则。

## 验证

用视频轨 4 秒、容器长约一帧的 MP4 覆盖旧快照和新上传。验证下一节点能处理旧快照形成的时间线，错尺寸或明显短的媒体仍失败，失效租约不能写回。不迁移数据库，不重新触发已失败的真实付费任务。

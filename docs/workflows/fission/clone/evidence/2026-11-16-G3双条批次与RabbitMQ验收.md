# 2026-11-16 · G3 双条批次与 RabbitMQ 验收

使用隔离 PostgreSQL 16、RabbitMQ 4.1.8、Erlang/OTP 27.3.4.12、本地工作存储和 FFmpeg。API Outbox 经真实 RabbitMQ 投递，由生成 Worker 的正式消费入口领取和回调。渲染与审片使用本地合成素材和故障注入。RabbitMQ 和 Erlang 使用发布 ZIP，在工作区临时目录启动回环实例。[RabbitMQ Windows 手动安装](https://www.rabbitmq.com/docs/install-windows-manual)

## 浏览器与持久化

- 选择两条时，预检显示每条两个镜头和全批 16 秒请求渲染时长。运行中刷新恢复同一批次和逐条进度。[预检确认](browser/2026-11-16-g3-two/01-双条生成预检.jpg)
- 第二条在保存第一个镜头后注入可重试故障。列表刷新后仍显示“部分完成”，第一条为“通过 · 待整批完成”，只出现一个重试按钮。两条都没有下载或归档入口。[刷新后部分完成](browser/2026-11-16-g3-two/02-刷新恢复部分完成.jpg)
- 重试后首条仍只有一次执行，第二条累计两次。供应商替身只收到第二条剩余镜头的创建，已保存的镜头随检查点复用。数据库发布两个视频和一份清单，两个 MP4 均能在浏览器加载预览，规格为 3 秒、720×1280。实际下载为 28,465 字节和 5,577 字节。[两条完成并归档](browser/2026-11-16-g3-two/03-同批两条已归档.jpg)
- 分别归档后刷新，两条均显示“已保存”，库中两份正式资产。再创建一批并取消，两个条目均取消，旧批仍有两个下载入口。两次批次共四条 Outbox 记录，均已发布。
- 1920、1440、390 像素宽度下页面和任务区域均无横向溢出。原型的生成区、条目卡和进度层级保留，数量来源为实际可选的一至两条，预览和逐条归档取自 API。[390 像素宽](browser/2026-11-16-g3-two/04-双条成片窄屏.jpg)

首次队列联调发现运行配置的额外字段被带入任务快照，使最后一步的批次指纹校验失败。生成配置和持久化都改为显式取模型字段，并加入快照字段和发布回归。使用新的隔离数据库复验通过。

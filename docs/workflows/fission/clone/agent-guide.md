# 裂变类·爆款复刻工作流指南

固定流程：`上传素材 → 深度拆解 → 元素映射 → 成片生成`

## 当前实现边界

正式系统的“裂变类 → 爆款视频复刻”沿用四节点工作台，已实现真实输入、深度拆解、元素映射、静音成片与批次交付。同一 `FISSION / FISSION_CLONE` Run 保存上传引用、商品事实、报告、映射和成片。正式入口使用服务端草稿、任务与确认产物。

新任务按参考片逐镜头复刻。深度拆解使用第 3 版完整指令，分析结构、创意、商品、镜头和视觉，记录音轨存在性。生成时每个镜头直接使用原片中对应的片段和已确认的目标配置。商品通过映射绑定同项目目标图片精确版本，历史报告里的道具作为镜头参考。单独更换道具使用[局部元素替换](../local-replace/agent-guide.md)。[逐镜头视频参考](plans/2026-11-23-逐镜头视频参考上线.md)

识别任务用已确认参考视频的采样图推断镜头边界，保留素材中识别到的字幕与贴纸以便预检。报告记录运镜、主体动作、接触遮挡和商品朝向，将证据不足的接触或松手时刻表达为观察区间，镜头时间线可跳到实际证据帧。报告的音频语义为 `UNASSESSED`。智能匹配仅依据候选资产元数据。[镜头内动作拆解](plans/2026-11-20-G2镜头内动作拆解.md)

G3 支持每批一至两条、720p 静音硬切、抽帧审片、逐条播放、下载和显式归档。逐镜头生成支持 1–15 秒、最多四个镜头、9:16 或 16:9 的参考片。每镜参考不足 2 秒时补末帧至 2 秒，每镜生成请求至少 4 秒，输出按锁定区间裁切。预检分别展示参考输入时长和请求渲染时长。音频与字幕保留、非硬切转场和已发布条目的局部重做仍待实现。[G3 双条批次与队列联调](plans/2026-11-16-G3双条批次与队列联调.md)

G4 的三至二十条入口由规划模型配置开启。规划只改变确认映射允许变化的场景维度。新批次按镜头 ID 冻结各自的静态布景，API 校验顺序与范围，渲染请求只消费当前镜头的场景要求。全批规划和独立审查分别保留检查点，审查通过才派发条目，全部条目通过审片才交付。整批 ZIP 包含有序 MP4 与精确版本清单。旧交付按原版本下载，清单标记待更新状态。批量画面质量仍待验收。[G4 差异化规划](plans/2026-11-17-G4差异化规划.md) · [历史十条真实批次验收](evidence/2026-11-17-G4十条真实批次验收.md)

新建三至二十条批次先派发首条，通过现有审片后自动派发其余条目。首条失败时余项尚未开始，可恢复故障按原快照重试，质量失败可取消后调整输入。最终仍需整批完成才能发布工作副本。原批次按照冻结的派发方式恢复。

逐镜头生成计划冻结原片身份、分镜帧范围、景别、运镜、构图、相对动作时点和目标图。Worker 只为当前镜头签取参考片段。审片按同一时间点配对原片与成片帧，核对机位、运镜、动作和目标。既有原片编辑和纯描述逐镜头任务按原模式和检查点恢复。[历史原片编辑](plans/2026-11-20-爆款复刻原片编辑.md)

历史 Mock 独立保留在 `CloneMockWorkspace.vue`，仅在显式 `VITE_FISSION_CLONE_MOCK=true` 时加载；其报告、任务、归档和导出均为演示，不迁移为真实业务数据。未绑定项目的正式模式提示选择项目。PID 自动取材和公共库入口不可用。

原型中旧版爆款采集、独立 Prompt 和独立渲染桥接不作为当前节点定义。[2026-10-20 前端验收](evidence/2026-10-20-前端原型还原验收.md) 只记录历史 Mock；实际检查与未验范围分别见 [G1 记录](evidence/2026-11-11-G1真实输入实现与验证.md)、[G2 记录](evidence/2026-11-11-G2拆解与映射实现验证.md)。隔离 Fake Provider 的流程验证不代表付费模型质量或日常环境部署。

## G1 输入与版本规则

- 四节点 ID 由 Contracts 的 `FISSION_CLONE_NODES` 定义：`CLONE_INPUT`、`CLONE_ANALYSIS`、`CLONE_MAPPING`、`CLONE_GENERATION`。输入、分析、映射分别提交 `clone-input`、`clone-analysis`、`clone-mapping`。
- 上传前登记有作用域与有效期的上传记录，大文件落磁盘临时区，经签名、类型、大小、媒体尺寸/时长和有界 FFmpeg 解码检查后写入工作区 `FileObject`。上传记录保护草稿文件；上传本身不创建正式项目资产或 WorkingArtifact。
- `WorkflowNodeState` 保存 `CloneInputDraft`，包括参考上传 ID、商品上传 ID 列表、商品名称、事实依据及来源使用确认。并发保存通过同项目/Run 锁与 expectedRevision 拒绝旧草稿；普通保存不增加确认产物 revision。
- 用户确认输入时，API 检查当前草稿版本、预期输入版本、所有文件的项目/Run/角色与可用性。只要求参考视频和来源使用确认。商品名称、事实依据与补充素材可选，替换目标图在元素映射时绑定。成功提交 `CLONE_INPUT / clone-input`；规范化内容相同不增 revision，内容变化才更新确认版及实际依赖它的下游状态。
- 暂停请求携带 `expectedCloneDraftRevisions`，覆盖所有已存在节点草稿，锁内逐项校验；仅有输入草稿时兼容旧 `expectedCloneDraftRevision`。重新进入恢复同一 Run，并提升所有节点草稿编辑 revision，阻止旧保存、确认或暂停。上传重试使用独立 attemptToken，旧尝试不能写入新结果。纯节点导航不确认输入、不启动任务。
- 文件仍被草稿或已确认产物引用时不能删除；先移除草稿引用，确认版仍使用的文件继续保留。仅未引用文件进入孤儿清理；关闭入口时保守保留复刻文件。
- 前端草稿保存串行化，切项目/Run 丢弃旧响应；切裂变模块先等待保存，失败保留当前编辑。资产入口按目标 workflowSpace 选择复刻模块，再恢复其 Run/节点。

## 启用与运行

`FISSION_CLONE_ENABLED` 和 `FISSION_CLONE_G2_ENABLED` 默认均为 `false`。G1 需迁移 `20261111120000_fission_clone_uploads`；G2 另需 `20261111130000_fission_clone_g2_tasks`。完成对应迁移和配置后，再按[本地开发指南](../../../development/local-development.md)核对并更新无活动任务的运行进程。关闭相应能力时不读取其新增表，并保守保护历史复刻文件、阻止不完整清理配置下的项目删除。

API 用 `FISSION_CLONE_FFMPEG_PATH`、`FISSION_CLONE_FFPROBE_PATH` 配置媒体工具，留空时从 PATH 查找。G2 任务还要求 `FISSION_CLONE_ANALYSIS_MODEL` 和 API/Worker 相同的独立 `FISSION_CLONE_ANALYSIS_WORKER_TOKEN`；Worker 使用 Ark 配置和可选 Compose profile `fission-clone-analysis`。[G2 Worker 运行说明](../../../../workers/fission-clone-analysis/README.md)

`FISSION_CLONE_G3_ENABLED` 默认关闭，依赖 G1/G2 和迁移 `20261116100000_fission_clone_generation_operation`、`20261116110000_fission_clone_generation_batch`。API 配置生成、审片模型名称。API 和 Worker 配置同一独立生成 Token。逐镜头视频参考与历史原片编辑需要可签发私有 TOS 读取地址的存储配置。缺少配置或媒体工具时任务明确失败。[G3 Worker 运行说明](../../../../workers/fission-clone-generation/README.md)

输入上限由能力接口返回：参考视频 MP4/MOV，最多 256 MiB（受更严格 `MAX_UPLOAD_BYTES` 限制）；商品文件 JPG/JPEG/PNG/WebP/MP4/MOV，每份最多 64 MiB，最多 20 份；视频 1–120 秒，媒体像素数不超过 4096×2160。这些是当前输入接收限制，不证明未来模型支持相同范围。

## G2 报告与映射规则

- 报告直接消费同 Run 当前 `clone-input` 的 `artifactId + revision + contentHash`，冻结商品事实、文件身份和媒体规格。阶段、镜头使用整数毫秒，连续覆盖源片；稳定 ID、元素双向引用、证据帧和占比均由服务端校验。采样画面的镜头边界是推断，不声明逐帧准确。
- 新上传优先登记视频轨时长。拆解对已确认历史快照容许最多 42 毫秒的探测误差，报告沿用已锁定时长，抽帧限于真实画面和锁定时长的交集。逐镜头参考归一化在这类旧快照中最多可复用一次末帧。[历史时长兼容](plans/2026-11-23-修复拆解时长兼容.md)
- `ANALYZE` 完整成功并通过校验后自动提交 `clone-analysis`，无需再加确认按钮。人工编辑保存到独立草稿，明确保存确认才提交，取消不改变确认版；并发草稿不得被任务完成或另一窗口取消覆盖。同内容不增业务 revision。
- 音频仅探测是否存在音轨，未实现语音转录、BGM/音效识别、静音区间或节拍检测；模型与人工保存均不得绕过当前能力边界。报告必须表达 `UNASSESSED` 原因，不能伪装为已检测事实。
- 映射同时记录当前 `clone-input` 和 `clone-analysis` 精确来源，按每个元素配置。所有产品必须 `REPLACE`；其他合法视觉元素可保留特征配置。替换目标需有效资产精确版本或明确内容/样式，产品不能仅填样式。结构锁由报告派生，冻结阶段、镜头顺序和时间边界、钩子与转化区间。
- 新确认映射只保留历史道具作为镜头参考。仍绑定旧替换的草稿由用户显式改为保留后确认，读取和导航不改写历史版本。逐镜头生成要求所有商品绑定 JPEG、PNG 或 WebP 图片版本，支持场景替换，其他元素沿用镜头观察作为参考。
- `SMART_MATCH` 只依据冻结候选元数据给出建议，候选记录 `assetId + version + sourceVersionId`；不为所有候选复制文件，也不虚构评分。只准备实际选中的资产并校验冻结身份。任务按创建时草稿 revision 写回；有并发编辑时保留为待采用建议，显式采用仍校验来源和当前草稿 revision。
- 文本内容策略与表现策略分开。字幕可显式发起 `VALIDATE_KEEP_TEXT` 核对原文字与目标商品事实，证据绑定两份来源及完整映射哈希；修改内容后旧证据失效。确认映射只校验已有证据，不隐式调用模型。文本核对通过不授予原音、音色或烧录原轨保留能力，这些模式当前仍被拒绝。
- 全部元素配置完整并通过服务端校验后，人工确认提交 `clone-mapping`。上游新确认只使真实引用它的既有下游待更新，不自动执行拆解、映射或生成。
- 任务复用 Outbox，领域 Task/Step 保存冻结快照、租约、attempt token 与检查点。取消、过期和旧回调不得提交；原快照重试验证来源和恢复预算。`PAUSED` 不等于取消，后台任务可合法完成。上游确认与依赖它的活动任务互斥，独立草稿仍可编辑。

## G3 成片与交付规则

- 预检只读。用户确认数量、每条镜头数、全批参考输入帧数和请求渲染秒数后，API 在项目与 Run 锁内重验当前确认映射、分析、输入及图片版本。双条批次登记已完成的同步规划，再创建两个带独立检查点的任务和 Outbox。后台无须等待页面在线。
- 镜头参考剪片、供应商创建意图、已知任务 ID、镜头文件、候选成片和审片结果按镜头或阶段持久化。参考片段只在创建意图登记前可签发，签名不写入检查点。有效重试验证原快照并恢复检查点。供应商明确拒绝创建时结束该任务，可修正后新建。创建结果未知时冻结同 Run 的新生成请求，待人工核查。
- 每个镜头保留首帧、中点帧、结束前一帧的抽样索引。告警、未通过或缺证据会阻断发布。全部条目通过后原子提交 `clone-video:<variantId>` 和 `clone-batch:<batchId>`。部分完成时仅投影任务状态，暂存文件保持引用保护。条目重试复用该条的有效检查点，取消整批则释放暂存引用。
- 失败任务卡可展开有效检查点中未通过或证据不足的镜头、审片原因及帧号。镜头编号取自任务冻结的时间线，技术失败或缺少有效审片记录时保留普通错误提示。
- 已发布的历史成片保留访问能力，并在实际消费的来源变化后标记待更新。显式归档根据成片 artifactId 和 revision 幂等写入项目资产库，列表从资产操作回执恢复归档状态。

## 业务目标

继承参考视频的结构与节奏，通过商品和元素映射直接生成复刻成片。前台不设置独立 Prompt 页面，也没有独立“视频渲染”节点。

| 节点     | 作用                                             | 直接上游               | 主要工作副本 | 直接下游      |
| -------- | ------------------------------------------------ | ---------------------- | ------------ | ------------- |
| 上传素材 | 上传参考视频、确认使用权限，可补充商品资料       | 项目资料               | 复刻输入包   | 深度拆解      |
| 深度拆解 | 分析结构、创意、商品、镜头、视觉，并记录音频状态 | 复刻输入包             | 六维拆解报告 | 元素映射      |
| 元素映射 | 绑定目标商品与场景，锁定原片镜头顺序与时长       | 拆解报告、当前项目资产 | 元素映射配置 | 成片生成      |
| 成片生成 | 逐镜头复刻、按原节奏合成、管理进度和交付         | 映射配置、锁定结构     | 复刻成片批次 | 项目归档/交付 |

## 固定规则

- 上传页不展示本地素材预处理卡片。
- 深度拆解按六维固定顺序展示；镜头维度使用纵向时间线。
- 元素映射后直接进入成片生成；不要恢复独立 Prompt 生成或独立渲染节点。
- 每条任务保存当时的映射快照，同时锁定参考视频镜头顺序与阶段占比。音频卡点属于后续音频能力。
- 必换产品未完成映射时不能生成。
- 成片生成页负责数量、进度、失败重试、删除、选择、分页与导出。

## 资产规则

上传素材进入工作区；当前项目选择器只看当前项目可用文件资产。选择资产时提交其精确版本，API 将该版本的文件复制为当前 Run 的暂存 FileObject，并保存来源资产 ID/版本，不直接绑定其他 Run 的可变文件。

映射准备文件、任务文件 hold、草稿和确认引用共同保护文件生命周期。其他项目素材须先通过项目资产库的快照导入成为当前项目资产。报告和映射保存为工作副本。用户可将生成成功的成片显式归档为当前项目的正式资产。

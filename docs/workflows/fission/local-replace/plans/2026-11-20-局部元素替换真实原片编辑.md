# 局部元素替换真实原片编辑

## 用户操作与验收

沿用「选择成片 → 选择时长范围 → 范围解析与替换 → 生成提示词 → 渲染输出」。从当前项目选择短视频及目标图片的精确版本，拖动原片或填写区间，标出一个可见商品或道具。提示词节点自动生成可编辑的替换说明，查看和普通导航均不发起模型任务。用户在输出节点确认后才创建一条任务，成功可播放、下载 MP4，并与原片对照查看。用小瓶实拍验收时换掉小瓶，保留方盒。

首版原片 4–15 秒、9:16 或 16:9、24–60 fps。完整原片和一张目标图提供给 Seedance 2.0，合成按原片时间精确取用编辑区间，区间外沿用原片画面。文件转码为 720p、24 fps，保留第一条原音轨。输出页面提供人工画面对照。人物、字幕、贴纸、音频替换、多对象和长成片编辑留待后续实现。

## 工作流与提交

使用本项目 `FISSION / FISSION_LOCAL_REPLACE` 工作流 Run、各自的节点导航与一个可恢复的编辑方案草稿。每次保存按当前草稿 revision 处理并发。前四步逐步编辑，渲染确认时写入 `local-replace-plan`，冻结原片、图片版本、用户指定对象、区间及指令。Outbox 仅携带项目、Run、任务标识，由局部替换队列处理。计划内容相同保持 revision。旧任务按其实际来源版本恢复，已有输出保留并按当前计划标记待更新。

任务完成时校验输出 MP4，并提交 `local-replace-video:<taskId>` 与精确计划引用。任务和成片全程使用自己的项目和 Run 作用域。服务端控制租约、取消、供应商任务号与幂等重试。供应商收到请求的结果无法确认时暂停该 Run 的新请求，避免重复扣费。供应商原片访问由带任务租约的短期签发提供。

API 与 Worker 通过共享契约连接。底层复用项目资产、工作副本、Outbox、存储、Seedance 传输和可共享的素材请求；爆款复刻保存自己的节点和历史版本。当前演示可在显式开发预览中查看。

## 验证与发布

- 验证资产跨项目拒绝、草稿并发、幂等、当前方案版本、过期任务回写、取消、同一供应商任务恢复和产物文件绑定。
- 用生成好的测试视频和模拟传输验收首段、中段、尾段与整片，检查原片范围外画面、音频和全片帧数；对照复刻回归。
- 在正式项目入口验证选片、选区间、指定对象、待处理、失败和成功下载。付费供应商效果、账号素材与生产发布单独核实。

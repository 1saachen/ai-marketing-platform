## 目标与首版范围

从正式入口「裂变类 → 数字人口播」在指定项目选择已授权的形象和音色，确认口播稿，生成可播放、可恢复的音画同步素材，编辑背景和字幕，经同步校验后导出可下载的 MP4，并在明确归档时形成项目资产。沿用现有单页工作台和固定的五个业务节点。本计划启动时，工作台的生成、入库和导出为浏览器演示。 [业务指南](../agent-guide.md) · [前端入口](../../../../../apps/web/src/workflows/fission/shared/FissionWorkflowPage.vue) · [API 模块](../../../../../apps/api/src/workflows/fission/avatar/README.md)

首轮内部试点建议采用已授权的预置人物素材、一个已验证的普通话音色、手工编辑或 TXT 导入文案、图片背景、可编辑字幕、9:16 1080P MP4 与可选 SRT。首条端到端验收样片建议 15–30 秒。扩大试点前补齐超过 60 秒的分段样本及接缝测量，语言、语速和片长按实测范围开放。文案辅助生成、方言和多音色、视频背景、品牌叠加、真人参考图制人、服装/姿态生成和声音克隆分别验收，按实际能力开放对应控件。 [产品需求与验收目标](../../../../../README.md)

- **接口与数据模型。** 先在 `packages/contracts` 定义节点、工作区投影、确认请求、版本引用、任务及媒体校验契约，同时覆盖 TypeScript 与 Worker 消费。用户接口按项目和 Run 提供工作区读取、节点确认、任务创建/查看/取消/重试、成片下载和归档。复用平台草稿、工作副本、依赖、文件角色和资产版本模型。实施时以加法迁移补齐 Avatar 任务、分段检查点、供应商操作 ID 和必要的授权记录，保存索引、作用域约束及唯一键。将活动任务、待对账操作及临时媒体纳入现有项目删除保护与回收。成功成片使用不可变文件对象，历史交付保存独立的版本引用。明确关联清理、持久化和授权读取规则后再替换当前副本。形象绑定、文案、同步、方案和成片分别保有稳定提交边界。API 使用共享错误契约返回可操作的中文原因。

## G2 首次接入范围

在已有 G0 单条真实回执的基础上，先接通口播片段生成与工作台预览。输入为当前 Run 的已确认数字人绑定与普通话口播稿，以及已选音色的授权资产版本。试点限单人 MP4、最长 30 秒、64 MiB 及最多 120 字。音色由运维对具体 `VOICE_PROFILE` 授权版本凭据登记批准的豆包普通话预设音色。语速使用已验证的供应商默认值。

创建请求带工作台草稿 revision、两个已确认工作副本引用和幂等键。运行中校验授权、Run、确认产物及语音选择快照。挂起或离开页面时后台继续处理原 Run。API 和 Worker 通过 `fission.avatar.sync.requested` 及独立租约协议协调。豆包受理状态不明时查询冻结操作标识，MediaKit 已受理任务按已保存任务 ID 查询。受理结果仍不明时停在待核对的错误状态。

导入完整的 MP3 音轨、MP4 口播片段和字级时间戳后自动提交 `avatar-sync`。媒体初检检验两轨可解码、时长和驱动音频一致性。实际发音与唇形的逐帧阈值、人物前景处理、超过 60 秒的分段调度，以及最终成片交付继续按各自阶段验收。

## G3 首次接入范围

背景配置读取同项目、同 Run 当前已确认且未待更新的 `avatar-sync`。编辑草稿绑定这一 revision，由用户确认后提交 `avatar-composition`。图片使用当前项目可用的场景与背景资产具体版本。保留同步片段的原画面，在 9:16 画布中等比居中，并显示四周所选的色彩或图片。人物前景抠像和原画面背景替换待前景能力验收。字幕用当前音轨字级时标生成起点，允许人工编辑和选择内嵌、SRT 或两种同时输出。

用户主动渲染时冻结已确认的方案和同步 revision，事务内写任务与 Outbox。专用渲染消费者用 FFmpeg 生成 1080×1920 MP4 和可选 SRT，分别核验媒体结构、首尾时长及音频与驱动音轨的一致性。候选成片进入待校验状态。只有独立口型测量绑定同一成片 SHA-256、使用已配置的校准方法、达到覆盖率和置信门槛，且最大配对事件偏差不超过 100 毫秒，才可提交 `avatar-output`。工作台仅从该已确认副本提供鉴权下载和明确归档。未配置测量方法时保留候选待校验，超标或失败保留旧交付。

数据库采用加法迁移，G3 渲染开关默认关闭。渲染消费者无需 TTS 或 MediaKit 密钥，背景或字幕确认仅触发后续用户选择的本地渲染。隔离验收覆盖两轮方案更新、任务重复与迟到提交、审核不通过阻断交付、当前素材授权复核、历史版本与跨项目读取、重复归档回执、真实 FFmpeg 文件及字幕输出。事件级检测的校准数据及长片运行验收沿用下节。

## G4 首轮长片预检

先在离线环境解决三件事。将长文案按自然停顿拆成满足现有单段字数上限的有序稿件。用逐段已经完成口播驱动的 MP4 和对应语音，验证超过 60 秒的合成、接缝、时间戳与断点恢复。对最终文件使用绑定摘要的人工标注评估，分别报告覆盖率、最大口型偏差及发音单元匹配准确率。离线文件和检查点放在仓库外的私有目录，通过文件指纹拒绝混用版本。沿用项目中的短片试点开关和交付门槛。

离线预检通过后，再将分段冻结到同一 Run 的已确认形象、口播稿和音色版本。父任务保留唯一活动约束，逐段记录语音与口型提交状态、已受理 ID、源文件摘要、结果摘要和租约。重领时使用已确认片段，受理结果未知的片段走对账。所有分段及合成验证通过后自动提交一个 `avatar-sync`；背景与渲染依赖该版本。正式接口通过加法迁移和独立开关启用有界试点，既有短片维持原契约。付费供应商长片样本和独立标注验收完成后，再根据真实时长、费用及队列监控结果放量。

工作台接入采用 61–90 秒有界试点，复用一段已授权形象，各段独立使用同一音色合成。`20261124130000_fission_avatar_segmented_sync` 保存分段，长片同步和长片渲染使用独立队列和 v2 媒体契约。长片渲染从确认方案及其引用的 `avatar-sync` 冻结接缝，实际产物的时间线通过复核后进入口型验收。核验必须包含与候选一致的片长和接缝，按发音单元记录的准确率至少 950‰。隔离验收以可控故障替身验证分段续跑，以及真实 RabbitMQ、FFmpeg、下载和归档。页内模式切换仅改变生成请求的规格。

### Seedance 尾帧接续对照

先做约 12 秒的独立样片。一次合成整稿配音，在实测停顿处分三段，将固定时长所需余量放在停顿内。两版共用最终音轨和 Seedance 生成的首段人物画面。现有方式复用首段素材，接续方式将上一段方舟原始尾帧作为下一段的 `first_frame`。原始尾帧在方舟同账号链路内传递，MediaKit 在其后使用对应音频切片对齐口型，评估使用最终合成的接缝。每个供应商提交意图和已受理任务单独记账，重跑以原任务 ID 查询。对照分别记录画面、动作及口型观感。本次真实运行需独立费用授权。 [Seedance 接口](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh) · [肖像素材适用条件](https://console.volcengine.com/ark/region%3Acn-beijing/docs/seedance-portrait-asset-guide)

### G4 尾帧接续实施

12 秒服务器对照验证了两次尾帧接续。接入复用唇形驱动的长片入口及现有任务、队列、租约和 `avatar-sync` 提交边界。冻结同 Run 的形象绑定和口播稿 `artifactId + revision`、具体音色和授权版本。开关默认关闭，启用后新建长片需从已确认形象的有效授权取得同账号的 Seedance 原始任务 ID。首段使用该任务可读取的原始尾帧，后续以刚生成的上一段原始尾帧为首帧。部署前核对原任务仍可读取，且其尾帧通过供应商肖像限制。已有短片及长片任务按创建时的执行输入恢复。 [服务器样片](../evidence/2026-11-24-Seedance尾帧接续对照预检.md)

Worker 只合成一次整稿语音，按实测时标与停顿将驱动规划成 Seedance Fast 支持的 4–15 秒整数段。API 存储音源摘要和完整分段计划，事务内创建各段的续跑记录。每段先登记画面提交意图、写入受理 ID、取得画面，再执行同段口型对齐。续跑按已受理的原任务查询，仅补做未提交操作。未知受理停止追加；签名尾帧只在 Worker 内存中由原任务查询传至下一段。全部切片和视频通过校验后自动提交 `avatar-sync`。背景和渲染继续引用实际提交的 revision，口型评审仍绑定最终成片。

加法迁移登记形象授权的原始任务 ID、冻结的切片计划和逐段画面回执。隔离验收覆盖旧契约、整稿配音与切片帧网格、原始尾帧原样传递、未知受理、旧租约、断点恢复，以及最终时标和媒体校验。61–90 秒的真实供应商运行和上线另行验收。

## 同步测量与导出门槛

1. **先检媒体结构。** 在同步素材和最终 MP4 上检查音视频轨、实际首尾 PTS、时长、解码和分段接缝，处理编码延迟和累积漂移。报告按毫秒记录首尾偏差和异常区间。该项验证轨道时间线，唇形还需下面的事件级测量。
2. **再检实际口型。** G0 以人工标注的发音和唇部动作校准检测，按有效口播窗口测最终解码文件中的配对事件，并覆盖全片首、中、末和每个接缝。保存测量方法版本、有效样本覆盖、置信度、每个失败区间和最大绝对偏差。有效窗口覆盖和置信度阈值在 G0 标定并冻结。可信窗口最大绝对偏差须 ≤100 毫秒，缺测或低置信进入待处理状态，超标及待处理均阻断本次交付。重新对齐可复用音频与可靠字幕时标，提交新的同步结果后由用户重新渲染。
3. **验证检测本身。** 人工标注样本覆盖正负 80、100、120 毫秒移位、尾端漂移、单个接缝错位、跳帧、无声和遮挡，并记录在边界上的误判。用独立样片复核最终输出，覆盖短片与超过 60 秒的有声长片。产品所列唇形匹配准确率 ≥95% 单列口径与标注样本，按有效发音单元报告正确比例，和 100 毫秒的时间偏差分别验收。 [工作流同步规则](../agent-guide.md) · [产品验收目标](../../../../../README.md)

## 迁移、发布与回退

1. 评审加法迁移、容量和索引后备份目标库，在隔离环境验证迁移及旧版本读取兼容。既有项目按首次进入或明确恢复建立真实 Run。Mock 浏览器数据保留在演示入口，需要的稿件通过正式文案导入进入生产。
2. 默认关闭 Avatar 新任务，按迁移、API/内部接口、独立 Worker、正式 Web 入口的顺序验证部署。检查实际运行版本、队列与权限，先打开指定试点项目，再依据 G4 结果放量。记录排队与执行耗时、分段重试率、失同步区间、成本及任务/操作追踪 ID。
3. 回退时先关闭新任务，按任务状态排空或受控取消 Avatar 队列，保留加法迁移、已授权的历史交付读取和审计记录。验证同环境其他工作流的队列与资产读取，并检查恢复上线时在途任务和供应商操作的对账。 [生产部署指南](../../../../development/server-deployment.md)

本计划推荐先做普通话、竖屏和预置授权人物的单条闭环。G0 需要确认可用资产与授权范围、可用供应商和样片预算、首版语种与时长上限，以及授权撤销后的存量交付访问规则。
